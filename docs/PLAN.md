Статус: утверждён 2026-10-23 (с правками пользователя). Этап 1 принят; этап 2 сделан 2026-10-23 и ждёт проверки.
Исходное ТЗ — разделы 0–13 первого сообщения. Этот файл фиксирует решения поверх ТЗ.

## 2. Навигация

Нижняя панель, 5 вкладок:

| Вкладка | Содержимое | Этап |
|---|---|---|
| Сегодня | Старт: по плану (1 тап) / пустая / из шаблона / повторить прошлую; активная тренировка | 1 |
| План | Неделя Пн–Вс, перенос тренировок между днями, «скопировать неделю», статусы | 1 (мезоцикл — 2) |
| Прогресс | Недельный отчёт, сигналы, план на следующую неделю, рекорды, графики | 2 (в этапе 1 скрыта) |
| История | Список тренировок, просмотр, редактирование | 1 |
| Ещё | Библиотека упражнений, шаблоны, настройки, экспорт/импорт, «О приложении»; позже «Цикл», замеры | 1–3 |

## 3. Экран тренировки

- Карточка упражнения: название, «План: 3×6–8 @RIR 2 · 82,5 кг», «Прошлый раз: 80×8, 80×8, 80×7».
- Строка подхода зависит от `trackingType`:
  - `weight_reps`: `[− вес +] [− повт +] [RIR] [✓]`;
  - `bodyweight_reps`: `[± доп. вес / ассист] [− повт +] [RIR] [✓]` (отрицательное значение = ассистирование);
  - `reps`: `[− повт +] [RIR] [✓]`;
  - `time`: `[− время +] [✓]`;
  - `weight_time`: `[− вес +] [− время +] [✓]`.
- Тип подхода: тап по номеру подхода циклически переключает разминочный (Р) → рабочий (1, 2…) → дроп-сет (Д) → до отказа (О). Разминочные визуально приглушены, не идут в тоннаж, рекорды, e1RM и подсчёт рабочих подходов.
- Автозаполнение:
  - первый подход упражнения: план на сегодня → прошлая тренировка с этим упражнением (тот же порядковый подход) → пусто;
  - следующие подходы: из предыдущего сегодняшнего подхода.
- «Как в прошлый раз» = подход уже заполнен, запись — 1 тап по ✓, с правкой — 2 тапа.
- Каждый ✓ сразу пишется в IndexedDB и запускает таймер отдыха (длительность — из шаблона, иначе из упражнения, иначе из настроек). `endsAt` таймера хранится в базе.
- Незавершённая тренировка — `Workout` с `finishedAt = null`, восстанавливается при открытии.
- Отмена: плашка «Отменить» ~5 с после каждого действия. Подтверждение — только для удаления.
- Меню упражнения: заменить на аналог, переставить, удалить, суперсет-группа, заметка.
- Wake Lock на время тренировки, где доступно.
- Завершение: итог (длительность, рабочие подходы, тоннаж, сравнение с планом), самочувствие 1–5 (опционально); если есть невыполненные подходы — удалить или отметить.

## 4. Защита данных и PWA

- `navigator.storage.persist()` при первом запуске, где поддерживается; результат виден в настройках.
- Подсказка установить приложение на главный экран (на iOS — инструкция «Поделиться → На экран Домой»).
- Раз в неделю — напоминание сделать JSON-бэкап; дата последнего бэкапа в настройках.
- Обновление service worker в режиме `prompt`. Во время активной тренировки обновление не предлагается.
- Без сторонних SDK аналитики.

## 6. Модель данных

Внутри: вес в кг, время в секундах, даты ISO 8601 UTC + часовой пояс пользователя. ID — UUID. Мягкое удаление (`deletedAt`). У всех сущностей `createdAt`, `updatedAt`. Версия схемы и миграции Dexie — с первого дня. В экспорте — `schemaVersion`.

Сущности — по разделу 10 ТЗ, с уточнениями:
- `WorkoutSet` вместо `Set` (конфликт имени с JS `Set`). Для `bodyweight_reps` поле `addedWeightKg` (отрицательное = ассист).
- `WorkoutTemplate` — в этапе 1: создать, редактировать, поставить в день недели.
- `PlannedWorkout.status`: planned / done / partial / skipped / moved; `workoutId` связывает с фактом; `Workout.plannedWorkoutId` — обратная связь. Статус выставляется при завершении тренировки (done / partial по доле выполненных подходов).
- `Workout.wellbeing` 1–5 — собирается с этапа 1.
- `RestTimer` — одна запись (`endsAt`, `workoutExerciseId`).
- `Settings`: единицы, вес грифа, RIR/RPE, отдых по умолчанию, коэффициент вспомогательной мышцы (0,5), пороги сигналов, учёт собственного веса в тоннаже, `lastBackupAt`, `persistGranted`.

## 7. Библиотека упражнений

- Источник: free-exercise-db (github.com/yuhonas/free-exercise-db), лицензия проверяется при загрузке. ~70 упражнений.
- Техника: перевод оригинальных `instructions` с сохранением смысла; `source` указывает на базу и id упражнения.
- Категория базовое/вспомогательное — из поля `mechanic` (compound/isolation), сверено с определениями NSCA; расхождения помечены.
- Частые ошибки — только с источником или с пометкой «требует проверки».
- Перед загрузкой в приложение — таблица на утверждение: упражнение, мышцы, атрибуты NSCA, облегчённые альтернативы, пометки (`docs/exercises-review.md`).

## 9. Этапы

### Этап 1 (MVP)
1. Каркас, PWA (prompt-обновление), тёмная тема, навигация.
2. `domain`: формулы и тесты (эталоны Epley 116,7 / Brzycki 112,5).
3. Данные: схема, миграции, экспорт/импорт, тесты.
4. Библиотека упражнений (после утверждения таблицы): поиск, фильтры, избранное, свои упражнения, «заменить на аналог».
5. Простые шаблоны: создать, редактировать, поставить в день недели.
6. Запись тренировки: типы подходов, строки по trackingType, автозаполнение, таймер, отмена, восстановление, самочувствие при завершении.
7. Недельный планировщик (статусы, связь с тренировкой, «скопировать неделю», перенос) и история.
8. Защита данных: persist, подсказка установки, напоминание о бэкапе.
9. Проверка: телефонный экран, офлайн, закрыть/открыть посреди тренировки, экспорт → очистка → импорт. Отчёт.

### Этап 2
Программы и мезоцикл, недельный отчёт и сигналы, план на следующую неделю и разгрузка, рекорды и графики, калькуляторы блинов и разминки.

Решения этапа 2:
- Схема данных v2: таблица `programs`, у `WeekPlan` — `programId`, `weekIndex`; у пункта плана — `targetReps` (цель «+1 повтор»). Миграции базы и файла экспорта v1 → v2.
- Отчёт и сигналы не кэшируются — считаются из подходов при каждом чтении, поэтому правка прошлой тренировки сразу меняет отчёт.
- Первое выполнение упражнения рекордом не считается (точка отсчёта).
- «В целевом RIR» = |RIR − цель| ≤ 1 (эвристика, настраивается).
- Готовые программы: только фулбади 3×/нед. и верх/низ 4×/нед. (ACSM 2009). Сплит по группам мышц не добавлен — нет проверенного источника на конкретную раскладку.
- Тренировка плана, завершённая без рабочих подходов, план не расходует (отвязывается).

### Этап 3
Модуль «Цикл», замеры тела, напоминания, CSV.
